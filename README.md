# AdaptiveBorderBlur / AdaptivePillarboxBlur

为 ReShade 6.x / 6.8 编写的 **自适应动态高斯模糊黑边 Shader**。

项目目前提供两个版本：

| 文件名 | 功能 | 推荐用途 |
|---|---|---|
| `AdaptivePillarboxBlur.fx` | 仅处理左右黑边 | 只需要传统 4:3 → 16:9 / 21:9 / 32:9 的用户 |
| `AdaptiveBorderBlur.fx` | 自动处理左右或上下黑边 | 需要完整宽高比自适应的用户 |

两个版本都会保留发布，用户可以根据自己的实际需求自行选择。

---

# 两个版本有什么区别？

## AdaptivePillarboxBlur

这是已经确认可用的左右黑边版本。

适用于：

```text
4:3 → 16:9
4:3 → 21:9
4:3 → 32:9
5:4 → 16:9
16:10 → 16:9
……
```

也就是：

> 当前显示器 / BackBuffer 比游戏内容更宽。

Shader 会自动在：

```text
┌───────┬──────────────────┬───────┐
│            │                             │            │
│ 动态高斯模糊 │         原始游戏画面          │ 动态高斯模糊 │
│            │                             │            │
└───────┴──────────────────┴───────┘
```

生成左右动态高斯模糊背景。

中央游戏画面不会被修改。

### 推荐给

- 主要玩传统 4:3 老游戏
- 显示器始终比游戏内容更宽
- 不需要处理上下 Letterbox
- 希望使用已经确认过视觉效果的稳定方案

---

## AdaptiveBorderBlur

这是全方向版本。

它会自动比较：

```text
显示器 / BackBuffer 宽高比
```

和：

```text
游戏内容宽高比
```

然后自行决定处理方向。

### 显示器更宽

例如：

```text
4:3 → 16:9
```

自动处理左右：

```text
┌──────┬─────────────────┬───────┐
│ 动态模糊  │         游戏画面             │  动态模糊   │
└──────┴─────────────────┴───────┘
```

### 显示器更高 / 更窄

例如：

```text
16:9 → 16:10
21:9 → 16:9
```

自动处理上下：

```text
┌───────────────────────────┐
│                 动态高斯模糊                  │
├───────────────────────────┤
│                                             │
│                  游戏画面                    │
│                                             │
├───────────────────────────┤
│                 动态高斯模糊                  │
└───────────────────────────┘
```

### 比例相同

例如：

```text
16:9 → 16:9
```

Shader 自动旁路，不添加任何边框。

# 主要特性

- 自动读取当前 ReShade BackBuffer 分辨率
- 不写死 1920×1080、2560×1440 或 3840×2160
- 不写死 16:9 显示器
- 支持 16:9、16:10、21:9、32:9 等不同显示器比例
- 支持 1080p、1440p、4K、5K、8K 等输出分辨率
- 游戏内容比例与显示器比例完全分离
- 中央游戏画面保持原样
- 黑边区域使用实时游戏画面生成动态背景
- 使用真正的 Separable Gaussian Blur
- 横向、纵向分别进行完整高斯卷积
- 高斯权重根据标准差 `σ` 实时计算
- 每个方向使用 65 个采样点
- 使用低分辨率中间纹理降低高分辨率下的性能压力
- 支持亮度、饱和度、模糊强度、边缘过渡等参数
- ReShade 面板全部使用简体中文
- 无需任何外部纹理
- MIT License

# 关于“自定义内容宽高比”

这是一个很容易误解的地方。

ReShade 面板中同时存在：

```text
游戏内容宽高比
```

和：

```text
自定义内容宽高比
```

其中：

> **“自定义内容宽高比”只有在“游戏内容宽高比”选择“自定义”时才会生效。**

例如当前选择：

```text
游戏内容宽高比 = 4:3
```

那么 Shader 会直接使用：

```text
4 / 3 = 1.333333...
```

此时无论怎样调整：

```text
自定义内容宽高比
```

画面都不会发生变化。

这是正常行为。

如果需要手工调比例，请先选择：

```text
游戏内容宽高比 = 自定义
```

然后再调整：

```text
自定义内容宽高比
```

例如：

```text
4:3    = 1.333333
5:4    = 1.25
3:2    = 1.5
16:10  = 1.6
16:9   = 1.777778
21:9   ≈ 2.333333
9:16   = 0.5625
```

推荐同时打开：

```text
显示计算出的边框遮罩
```

这时 Shader 计算出的黑边区域会显示为洋红色，可以非常直观地检查比例设置是否正确。

# 高斯模糊实现

两个版本都使用真正的 **Separable Gaussian Blur**。

高斯权重按照标准公式计算：

```text
weight(x) = exp(-(x²) / (2σ²))
```

处理流程：

```text
原始 BackBuffer
        ↓
1/8 线性分辨率降采样
        ↓
横向 Gaussian Blur
        ↓
纵向 Gaussian Blur
        ↓
映射到黑边区域
        ↓
最终合成
```

高斯核半径：

```text
Radius = 32
```

采样范围：

```text
-32 ... 0 ... +32
```

因此每个方向共有：

```text
65 taps
```

横向卷积完成后，再执行一次纵向卷积。

相比使用少量纹理采样点并扩大采样间距的简单模糊，这种方式能够得到更加连续、均匀、柔和的高斯模糊效果。

---

# 性能设计

直接在完整 4K BackBuffer 上执行大半径 Gaussian Blur 成本很高。

因此模糊阶段会先将画面缩小到原分辨率的：

```text
1/8 宽
×
1/8 高
```

例如：

```text
3840×2160
```

模糊阶段实际处理的中间纹理约为：

```text
480×270
```

之后执行：

```text
65 taps 横向 Gaussian
+
65 taps 纵向 Gaussian
```

最后再将结果用于实际黑边区域。

由于最终目标本身就是强模糊背景，因此这种降采样可以显著减少 GPU 开销，同时保持柔和的视觉效果。

# 参数说明

## 游戏内容宽高比

设置真正游戏内容的比例。

不是显示器比例。

例如游戏本身是传统 4:3：

```text
游戏内容宽高比 = 4:3
```

即使以后显示器从：

```text
16:9
```

更换成：

```text
21:9
```

或者：

```text
32:9
```

这里仍然保持：

```text
4:3
```

显示器比例会自动读取。

---

## 自定义内容宽高比

只有：

```text
游戏内容宽高比 = 自定义
```

时才生效。

如果使用其他预设值，这个滑块不会参与实际计算。

---

## 边框取样缩放

控制动态背景从中央游戏画面取样的范围。

默认：

```text
1.00
```

提高以后，动态背景会更偏向使用靠近游戏画面边缘的内容。

在非常强的 Gaussian Blur 下，小幅改变这个参数可能不容易观察，因为大量空间细节已经被模糊掉。

---

## 高斯模糊强度

范围：

```text
0 ～ 100
```

一般可以理解为：

```text
0
基本不模糊

30～45
轻度模糊

50～65
普通背景模糊

70～90
强烈动态背景模糊

100
最大模糊
```

---

## 边框亮度

控制动态模糊背景的亮度。

```text
1.00
```

表示基本保持原亮度。

例如：

```text
0.70
```

表示将背景压暗。

如果 Shader 中将：

```hlsl
ui_min = 0.00;
```

则可以一直调到：

```text
0.00
```

也就是完全黑色。

---

## 边框饱和度

控制动态背景的颜色饱和程度。

```text
0.00 = 灰度
1.00 = 基本保持原色
>1.00 = 提高饱和度
```

---

## 边缘过渡宽度

控制：

```text
中央清晰游戏画面
        ↓
动态高斯模糊背景
```

之间的过渡距离。

它只影响靠近中央游戏区域边缘的一小段范围，不会改变整个边框的模糊程度。

---

## 边框填充不透明度

```text
1.00
```

表示完全使用新的动态背景覆盖原始黑边。

降低后会逐渐混回原本的黑边。

由于原黑边通常是纯黑，因此：

```text
降低亮度
```

和：

```text
降低填充不透明度
```

在部分画面中会产生较接近的视觉效果。

---

# 显示计算出的边框遮罩

这是诊断选项。

打开以后，Shader 当前判断出的黑边区域会显示为洋红色。

推荐在：

- 第一次配置
- 使用自定义比例
- 更换显示器
- 更换游戏
- 怀疑比例计算不正确

时临时打开。

正常游玩时关闭即可。

# 超宽屏处理

当边框非常宽，例如：

```text
4:3
→
32:9
```

动态背景不会简单把游戏画面最后一列像素无限拉宽。

Shader 会使用镜像折返方式继续从中央内容取样，使特别宽的背景仍然保持动态画面结构。

---

# Technique 顺序

一般建议放在大多数主体画质 Shader 之后：

```text
原始游戏
↓
Tonemap / HDR
↓
颜色调整
↓
锐化
↓
AdaptiveBorderBlur / AdaptivePillarboxBlur
```

这样动态背景会基于已经处理后的最终游戏颜色生成。

实际也可以根据自己的 ReShade Preset 调整顺序。

# 重要限制

## ReShade 必须能够看到黑边

这是最重要的前提。

例如显示器是：

```text
3840×2160
```

### 可以正常工作

游戏 BackBuffer 本身就是：

```text
3840×2160
```

而实际 4:3 游戏画面位于中央：

```text
2880×2160
```

左右各有 480 px 黑边。

这种情况下黑边属于 ReShade BackBuffer，Shader 可以正常绘制。

---

### 无法处理

如果游戏真正只输出：

```text
2880×2160
```

然后由：

- GPU Scaling
- 显卡驱动
- 显示器硬件缩放

在 ReShade 处理完成以后，才补成：

```text
3840×2160
```

那么那些黑边根本不属于 ReShade 能看到的 BackBuffer。

这种情况下任何 ReShade Shader 都无法在这些区域绘制内容。

---

# 为什么不自动识别游戏内容比例？

目前不会通过画面像素自动猜测：

```text
4:3
5:4
16:9
21:9
……
```

因为单纯检测黑色像素很容易在这些情况误判：

- 黑屏
- Fade In / Fade Out
- 夜间场景
- 黑色 UI
- 过场动画
- Letterbox 演出
- 菜单
- 黑色边缘特效

因此目前采用：

```text
显示器 / BackBuffer 比例
        ↓
完全自动读取

游戏内容比例
        ↓
用户明确指定
```

这种方式更稳定、更可预测。

# 应该选择哪个版本？

## 推荐 AdaptivePillarboxBlur 的情况

你的用途基本固定为：

```text
4:3 老游戏
→
宽屏显示器
```

而且只会出现左右黑边。

那么：

```text
AdaptivePillarboxBlur
```

已经足够。

---

## 推荐  AdaptiveBorderBlur 的情况

你希望一个 Shader 同时应对：

```text
左右 Pillarbox
+
上下 Letterbox
```

或者经常更换：

- 游戏比例
- 显示器比例
- 超宽屏
- 16:10 显示器

那么可以使用：

```text
AdaptiveBorderBlur
```

它会自动判断当前需要填充的方向。
